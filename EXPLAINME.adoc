== Claim-to-implementation map

=== E is an indexed endofunctor with incremental lawful/factive/belief layers

[quote, README.adoc]
____
The base interface treats E as an indexed endofunctor. Stronger structure is added incrementally, each as a separate record.
____

How this is implemented::
`link:src/EpistemicTypes/Base.agda[]` defines `Modality` (fields: `E`, `map`), `LawfulModality` (fields: identity, composition), `FactiveModality` (field: `reflect`), `BeliefModality` (intentionally no `reflect`), `ReturnModality` (field: `return`). Each is a separate record. No module postulates monadic `bind` or comonadic `extract`.

Caveat::
This is standard type-theoretic packaging of modal interfaces. The contribution is the *separation* — forcing the user to opt into factivity or strong introduction rather than inheriting it from a monad/comonad default. No known gap.

=== Warrants separate evidence tokens from soundness

[quote, README.adoc]
____
A warrant records the type of evidence for a claim without assuming the evidence is valid.
____

How this is implemented::
`link:src/EpistemicTypes/Warrant.agda[]` defines `Warrant κ A` (type of evidence tokens), `Epi κ A` (token + warrant), and `SoundWarrant` (separate interface adding `soundness : Epi κ A → A`).

Caveat::
`SoundWarrant` is an optional interface. Nothing in the core forces warrants to be sound. This is the right default for security/attestation use cases where the receiver must verify locally, but it means `Epi κ A` cannot be used as a drop-in replacement for `A` without assuming `SoundWarrant`.

=== Accessibility is a preorder with transport

[quote, README.adoc]
____
Standpoint access is modelled by a preorder κ ≤κ κ' (read: κ' is at least as informed as κ). Transport increase moves epistemic availability along this order.
____

How this is implemented::
`link:src/EpistemicTypes/Access.agda[]` defines the preorder (`_≤κ_`, `reflκ`, `transκ`) and `increase : κ ≤κ κ' → E κ A → E κ' A`. Preorder and transport laws are fields, not proved, because arbitrary standpoints do not determine them.

Caveat::
This is a standard Kripke-style accessibility relation, repackaged as an explicit record. The laws are assumed (fields), not derived. This is honest — the prototype does not constrain the accessibility relation beyond preorder.

=== Store views, residues, and resource bounds

`ReadConsistency.agda` uses finite store histories. Every read view proves its
value agrees with its indexed history; cached reads additionally prove ancestry.
Writes preserve the old sample and make it stale. Synchronization obtains the
current contents in the model. Evidence survives changes only through an
explicit stability proof. These results do not establish an external scheduler
or shared-memory implementation.

`EchoBridge.agda` replaces the unconstrained residue token with `Echo C y`, whose
certificate means `Retention.Cert C residue y`. `MatchesSource` establishes
compatibility with a candidate source, not unique historical origin. Recovery
and migration require their own laws. The examples prove useful migration of a
retained component and refute every adequate migration of a discarded component.

`BoundedEcho C measure budget y` keeps resource bounds separate from retention.
The concrete surreal adapter weakens a proved upper bound and preserves the
data; it no longer changes an unconstrained grade label. `daySurrealAccess`
remains a finite-day example, with no full Conway-surreal or physical-cost claim.

`tests/integration/CanonicalEcho.agda` imports the actual sibling sources and
proves representation round trips and lowering agreement. This optional gate
uses the standard library; the core continues to use builtins only. See
link:docs/continuity-foundations.adoc[] for assumptions and reproduction.

=== Proof transport entails an explicit claim meaning

How this is implemented::
`src/EpistemicTypes/ProofTransport.agda` takes `Meaning` and `Payload`.
`CertificateCheck` provides an executable check plus acceptance soundness.
`asProofUnder` requires the check to return true. `proofSound` derives the
exact holder/artefact/claim meaning, and `proofCannotSupportFalse` excludes
proof status for a refuted meaning. Public portability requires a supplied
implication between the holders' meanings.

Caveat::
The former token-only model did not justify semantic soundness.
`proofNeedsChecker` alone was only a structural statement. The new Boolean
examples and deliberate rejection controls test both acceptance and false
claims. The theorem remains relative to the specified meaning and checker
proof; it does not establish cryptography or physical facts. See
link:docs/proof-transport.adoc[].

== Known gaps

[CAUTION]
====
**No Kripke semantics.** The prototype defines the syntactic/type-theoretic interfaces for modalities but does not model them against a Kripke frame semantics. This is the largest open theoretical gap.
====

[CAUTION]
====
**No monadic or comonadic structure.** `bind` and `extract` are intentionally omitted. This keeps the prototype minimal but means `E κ` cannot be used as a drop-in for standard monadic effect handling without the user supplying these operations and proving their laws.
====

[CAUTION]
====
**SurrealBridge is finite-birthday only.** The concrete instance uses `Nat`. The full Conway proper class of surreals is not formalised. The module name may overclaim the mathematical structure.
====

[CAUTION]
====
**Access laws are assumed, not derived.** `EpistemicTypes.Access` takes preorder and transport laws as fields. This is honest (arbitrary standpoints don't determine them) and the laws must be supplied for each instance; the repository includes small concrete instances.
====

[CAUTION]
====
**Combined semantics remain open.** The residue correspondence is checked, but a combined Firmboot calculus, external-store correspondence, scheduler bounds, and runtime refinement are not established.
====
