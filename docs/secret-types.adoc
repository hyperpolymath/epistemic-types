This note records the theoretical half of the *silo* design. It sits upstream of
the practical incubator entry (`ideas-to-alphas/silo/`) and downstream of the
proved grade algebra (`trope-checker/spec/calculus.adoc`, Lean 4). The claim is
narrow and, I think, sound: *secret types are epistemic types read at the opposite
polarity*, and almost every part is already built in this estate. What is new is
one lattice and one linearity layer.

== The duality in one line

An epistemic type `E κ A` asserts _availability_: `A` is known/observable from
standpoint `κ`. A secret type `S ℓ A` asserts the _obligation_ dual: `A` may be
observed only from standpoints at or above clearance `ℓ`. Same accessibility
structure; opposite sign. Information-flow control is epistemic logic with the
arrows reversed — where epistemics says "κ *has* access", security says "only
`≥ ℓ` *may* have access".

[cols="1,1",options="header"]
|===
| Epistemic (this library) | Secret (the dual)

| `E κ A` — available from κ
| `S ℓ A` — releasable only to `≥ ℓ`

| `Access` preorder `κ ≤κ κ'` (§`Access`)
| The *security lattice* — Denning's model, verbatim. Flow only upward.

| `increase : κ ≤κ κ' → E κ A → E κ' A`
| `classify : ℓ ⊑ ℓ' → S ℓ A → S ℓ' A` — always sound; you may always over-classify.

| `ReturnModality` (`return : A → E κ A`)
| Classification (labelling a plaintext). The strong intro rule.

| `FactiveModality.reflect : E κ A → A`
| *Declassification.* Unrestricted `reflect` = total security failure.

| `BeliefModality` — *deliberately no* `reflect`
| **This is the security property.** A secret type is a modality you cannot
  extract from. The separation of the interfaces (`Base.agda`) *is* the theorem.
|===

The last row is the crux and it is already in the code. `BeliefModality`
intentionally omitting `reflect` was written for epistemic reasons — belief is not
factive. Re-read at security polarity it says exactly the right thing: *you can
carry a secret around, `map` under it, pass it on — but you cannot open it.* No
generic eliminator escapes the modality.

== The label lattice — the one genuinely new object

Everything above reuses `Access`. The new content is the choice of index category.
`Access` is a bare preorder; a security label wants a *lattice* stem:[(L, \sqcup,
\sqcap, \bot, \top)] so that combining two secrets has a defined clearance
(`ℓ₁ ⊔ ℓ₂`) and `⊥` = public, `⊤` = maximally secret. This is a strengthening of
`Access`, not a replacement — the same `increase`/`classify` transport, now over a
lattice. Concretely it is a new module `src/EpistemicTypes/Secret.agda` with
`Access` as its import, and a `SecurityLattice` record extending the preorder with
join/meet and their laws.

== Grades: RMR and RMO are the two ends of `Echo`

`EchoBridge.agda` now separates certified `Echo C y` residues from resource
bounds (see `continuity-foundations.adoc`). The following older graded-loss
notation is a design sketch, not the current API, in the
min-plus (tropical) order. Read at security polarity, the grade *is the
declassification budget*, and the two file primitives of the MAA framework
(`januskey`, `valence-shell`) are its endpoints:

[cols="1,1,2",options="header"]
|===
| grade `r` | primitive | meaning

| `r = 0` (tropical identity)   | *RMR* | zero loss — fully reversible release
| `0 < r < ∞`                   | _(unnamed)_ | measured, partial declassification — a budget in bits
| `r = ∞` (tropical absorbing)  | *RMO* | total loss — provably irrecoverable
|===

RMR and RMO are not two unrelated tools. They are the bottom and top of one graded
modality, and the middle row — declassification with a *quantified* leak — is the
open, interesting territory that nothing off-the-shelf expresses. Rust's `secrecy`
crate is binary (`Secret<T>`, redact + zeroise); it cannot state "this audit record
leaks at most `r` bits about the key". `Echo r` can.

== The grade algebra is already a security theorem (Lean 4)

`trope-checker/spec/calculus-v0.2-draft.adoc` proves, sorry-free, that the grade
carrier under composition stem:[\triangleright] is a *non-commutative product
monoid* over `Fate⁴ × Bond × Merge`, that it is *not* special-Frobenius, and that
it is cancellative only on the honest, finite-fidelity core (`instMonoid`,
`grade_mul_not_comm`, `grade_conical`, `grade_not_leftCancel`,
`honest_fidelity_cancel`).

Re-read at security polarity, *the refutation of CF is the erasure guarantee*. "CF"
(cancellative + conical ⇒ a lossless split/merge) failing means secrets cannot in
general be losslessly split and re-merged; the deceptive bottoms
(`Falsified` / `Misbound` / `Conflated`) are left-absorbing and break
reversibility. `Conflated`-absorbing = "once conflated, provably unrecoverable" =
RMO living inside the algebra. Irrecoverability is thus an *algebraic* fact already
discharged, not a runtime hope. This is the strongest single reason to build secret
types on the trope grade rather than a fresh scalar.

== Category-theoretic placement

* `S ℓ A` is a *graded comonad*; equivalently, reading a secret is a *coeffect*
  (Petricek–Orchard–Mycroft), graded by clearance. Coeffects are precisely "what
  the context must supply to use this value" — which is what a clearance _is_.
* `Echo r A` is a *graded (co)monad* / graded exponential; declassification is its
  graded counit, and RMR/RMO are the counit at grades `0`/`∞`.
* The whole is a category *enriched over the grade monoid* — which is exactly what
  the trope calculus already is, interpreted for property-instances instead of
  secrets. The transfer is a re-indexing, not a re-derivation.

== Why constructive, not classical

The natural question — could classical type theory beat the (intuitionistic, modal)
epistemic approach — has a precise answer: *the decisive axis is linearity, not
classicality*. The tool that models "use exactly once, then destroyed" is a
*linear* type (QTT multiplicity `1`, already available in the estate's Idris2), not
classical logic. A multiplicity-`1` secret cannot be duplicated or silently
dropped — that is the self-destruct, enforced by the checker.

Classical *linear* logic does add one genuine thing an intuitionistic setting
lacks: an involutive negation stem:[A^{\bot\bot} = A], which makes secret/public a
true de Morgan *polarity pair* rather than two unrelated modalities. But full
classical type theory (LEM, double negation) *destroys canonicity* — you lose
proofs-as-programs, and with it the ability to *extract* a verified runtime
(`tropecheck`) from the proofs. For a security tool whose whole value is a verified
extracted binary, that cost is disqualifying. The resolution: stay constructive
(Agda / Idris2 / Lean, as now), and take only the *polarised / linear* structure
from the classical side (call-by-push-value, polarised linear logic). The estate is
already sitting in the right place; the move is to add the linear layer, not to go
classical.

== What is built, and what is new

[cols="1,3",options="header"]
|===
| Component | Status

| Modal/epistemic base | *built* — this library (`Base`, `Access`, `Warrant`)
| Graded loss algebra | *built + Lean-proved* — `trope-checker` grade monoid
| Executable checker over an IR | *built* — `trope-checker` (`tropecheck`)
| Reversible / obliterate runtime | *built (partial)* — `valence-shell` RMR/RMO
  (7 assistants); RMO runtime primitives are stubs, 1 open Coq gap
| *Label lattice* (`SecurityLattice`) | *new* — the one object above
| *Linear single-use layer* (QTT `1`) | *new* — the self-destruct
|===

Secret types are therefore not a from-scratch project. They are a *join*:
instantiate the trope grade on a clearance lattice, add the multiplicity-`1` layer,
reuse the checker. The practical realisation — how a runtime handle embodies `S ℓ A`
and how destroying a vault key realises RMO soundly — is in `ideas-to-alphas/silo/`.
